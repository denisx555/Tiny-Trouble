# Tiny Trouble Lobby Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать согласованное стартовое 3D-лобби Tiny Trouble, открыть его в Unity и сделать код понятным для начинающего разработчика.

**Architecture:** Сохранённая сцена uGUI поверх 3D-персонажа и платформы. Editor-builder один раз создаёт редактируемые объекты, материалы и prefab; runtime-компоненты только переключают панели, применяют настройки, анимируют персонажа и загружают SampleScene.

**Tech Stack:** Unity 2022.3.62f3, Built-in Render Pipeline, uGUI 1.0.0, Unity Test Framework, локальный Unity MCP. Legacy Input Manager уже включён (`activeInputHandler: 0`).

**Spec:** `/home/denis/Tiny Trouble/docs/superpowers/specs/2026-10-10-lobby-design.md`

Короткие пояснения к техническим словам ниже:

- **Runtime** — код, который работает во время игры; **Editor-builder** — код,
  создающий сцену по команде в редакторе. **Prefab** — сохранённый шаблон героя.
- **Метод** — именованное действие в коде, например `SelectTab` открывает вкладку.
  **Параметр** — переданное методу значение; **массив** — список значений.
- **API / контракт / Interfaces** — имена методов, их параметры и результаты,
  на которые рассчитывают остальные файлы. Их сохраняем при этой правке.
- **PlayerPrefs** — встроенное хранилище настроек; **SerializeField** — отметка
  поля, чтобы Unity сохраняла его и показывала в панели свойств Inspector.
- **Play Mode** — запуск игры кнопкой ▶ в редакторе; **EditMode-тест** — проверка
  без запуска игры; **PlayMode-тест** — проверка во время игры; **suite** — все тесты.
- **MCP** — связь помощника с уже открытым Unity. **Reflection** — поиск класса
  или метода во время работы программы. **Assertion** — проверка ожидаемого результата.
- **Renderer** рисует поверхность, **материал** задаёт её цвет и блеск,
  **Collider** отвечает за столкновения. **Raycast** находит элемент под указателем.
- **Canvas** — поверхность интерфейса; **EventSystem** передаёт ему нажатия.
  **Persistent listener** — связь кнопки с методом, сохранённая в сцене.
- **Mock** — учебная или тестовая подмена настоящего объекта; здесь нужны реальные кнопки.
- **Коммит** — сохранённый шаг истории Git; **ветка** — отдельная линия изменений.
  **Review** — просмотр работы на ошибки; **SHA** — контрольный отпечаток файла.
- **`.meta`** — файл, по которому Unity узнаёт объект и сохраняет ссылки на него.

## Global Constraints

- Unity 2022.3.62f3, существующий Built-in Render Pipeline и установленные пакеты проекта.
- Интерфейс — uGUI Canvas поверх 3D-сцены, с поддержкой мыши и клавиатуры.
- Шрифт должен поддерживать кириллицу.
- Базовый размер 1920×1080; проверить 1280×720 и 2560×1440.
- Вкладки «Играть», «Персонаж», «Настройки» и кнопка «ИГРАТЬ».
- Четыре цвета толстовки — жёлтый, голубой, красный и фиолетовый.
- Громкость 0–100%; значение по умолчанию — 100%.
- В Build Settings Lobby идёт первой, SampleScene — второй. Содержимое SampleScene сохраняется.
- Меню не строится заново из кода при каждом запуске.
- Не скачивать платные ассеты и не использовать сторонний сервис генерации.
- Следовать текущему `AGENTS.md`: объяснять изменения по-русски небольшими шагами;
  новые термины пояснять, а посильные учебные задания оставлять пользователю.
- Перед объявлениями в C# писать XML-комментарии `///` с `<summary>`, `<param>`,
  `<returns>` и `<remarks>` по смыслу. `//` и `/* ... */` разрешены только внутри
  тел методов и свойств. Комментарии обновлять вместе с кодом.
- Перед запуском Unity проверять существующий экземпляр; при перезапуске сначала
  сохранить проект, закрыть старый процесс и дождаться его завершения.

## Review Focus

1. Повреждённые PlayerPrefs: некорректный индекс цвета и нечисловая громкость не ломают запуск (Task 1).
2. Смена цвета не окрашивает кожу, штаны, платформу и другие экземпляры prefab (Task 2).
3. Скрытая панель и её клавиатурное выделение не перехватывают ввод (Task 2).
4. Повторный клик «ИГРАТЬ» во время загрузки не запускает вторую загрузку (Task 2).
5. Настройки и ссылки сцены сохраняются после выхода из Play Mode, переоткрытия сцены и перехода в SampleScene (Tasks 1–3).
