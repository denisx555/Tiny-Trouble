# Пользовательские предпочтения

- Сообщения коммитов (заголовок и описание) всегда писать на русском языке,
  если пользователь явно не попросил другой язык.

# Актуальность README

- Регулярно обновлять `README.md` по мере развития проекта.
- При изменении возможностей игры, статуса разработки, порядка запуска,
  зависимостей, структуры проекта или проверок обновлять соответствующие
  разделы README в рамках той же задачи.
- Перед завершением задачи проверять, соответствует ли README текущему
  состоянию проекта; при необходимости обновлять описания и скриншоты.

# Работа с Unity

- Перед запуском Unity проверить, не открыт ли уже `/home/denis/Tiny Trouble`.
- Если проект уже открыт, использовать существующий редактор через Unity MCP.
- При необходимом перезапуске сначала сохранить сцены и ассеты, закрыть старый
  экземпляр и дождаться фактического завершения его процесса. Только затем
  запускать новый экземпляр. Не открывать второй редактор с этим же проектом.

# Обучение пользователя программированию

- Пользователь — начинающий разработчик без навыков программирования.
  Объяснять по-русски максимально простым и понятным языком, небольшими шагами.
  Новые термины сразу пояснять на конкретных примерах из проекта.
- Совмещать разработку с постепенным обучением: перед изменениями кратко
  объяснять их цель, после — как работает результат и как его проверить.
- Периодически давать небольшие задания по написанию кода, связанные с текущей
  задачей и соответствующие уже освоенным знаниям. Указывать файл, место
  изменения, ожидаемый результат и способ проверки.
- Часть посильной работы оставлять пользователю. Сначала давать подсказку
  и возможность попробовать, затем проверять его код и спокойно разбирать
  ошибки. Не выдавать сразу готовое решение учебного задания.
- По просьбе пользователя мягко настаивать на самостоятельной практике:
  при отказе предложить ещё более простой шаг и помощь, а не сразу делать
  всё за него. Не стыдить и не давить; явную просьбу остановить или отложить
  обучение уважать.

# Комментарии в коде

- Комментарии в создаваемом и изменяемом коде обязательны, особенно в C#.
- В C# использовать XML-комментарии документации: `/// <summary>` для
  назначения классов, методов и полей; `/// <param>` для параметров,
  `/// <returns>` для результата и `/// <remarks>` для пояснения шагов логики.
  Размещать их перед соответствующим объявлением, чтобы объяснение было видно
  при наведении в редакторе кода. Обычные `//` и блочные `/* ... */` допускаются
  только внутри тела метода или свойства для пояснения отдельных шагов;
  перед объявлениями использовать XML-комментарии.
- Писать комментарии на русском языке, предельно простыми и понятными
  для начинающего словами. Если нужен технический термин, сразу пояснять его.
- Объяснять назначение классов и методов, смысл важных переменных и основные
  шаги логики, чтобы пользователь мог понять код и учиться по нему.
- При изменении кода обновлять связанные комментарии, чтобы они соответствовали
  тому, как код работает сейчас.
